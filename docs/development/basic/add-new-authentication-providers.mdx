# Authentication Providers (Per-Tenant SSO)

LobeHub Enterprise has no built-in provider presets (Google, GitHub, Microsoft, Auth0, Keycloak and so on) and no deployment-wide SSO environment variables. The upstream way of adding a provider (a definition file under `src/libs/better-auth/sso/providers`, `AUTH_<PROVIDER>_*` variables and `AUTH_SSO_PROVIDERS`) no longer exists in this codebase, and none of those variables is read.

Each tenant configures its own sign-in providers. Admin stores them in the tenant's `sso_providers` table, with the client secret sealed per tenant, and the tenant's [Better Auth](https://www.better-auth.com/) instance serves them through its generic OAuth plugin.

## Supported provider kinds

| Kind             | `protocol` / `preset` | What you configure                                                                                     |
| ---------------- | --------------------- | ------------------------------------------------------------------------------------------------------ |
| OIDC             | `oidc`                | Issuer (or discovery URL), client ID and secret. Scopes default to `openid email profile`; PKCE is on. |
| Generic OAuth2.0 | `oauth2` / `custom`   | Authorization, token and user info endpoints, client ID and secret. Scopes default to `profile email`. |

Any vendor that speaks one of the two (Okta, Entra ID, Google, Keycloak, a company IdP) is configured as one of them. The provider ID is only a name chosen by the tenant administrator: a provider called `okta` or `google` is a plain OIDC client, never a vendor preset. A stored row of any other kind (SAML, a named OAuth 2.0 vendor from an older build, an unusable configuration) is skipped on its own and does not affect the tenant's other providers.

## Callback URL

Register this redirect URL with the identity provider:

```
https://<host>/t/<tenant-slug>/api/auth/callback/<providerId>
```

The request proxy forwards it to Better Auth's generic OAuth callback (`/oauth2/callback/<providerId>`) inside that tenant.

## Where it runs

- `apps/server/src/services/tenantSso` loads the tenant's enabled rows, opens the secrets, runs OIDC discovery (with SSRF protection) and turns each row into a Better Auth generic OAuth configuration (`toGenericOAuthConfig`).
- `src/libs/better-auth/tenant-sso.ts` builds the per-tenant provider set and skips rows this build cannot run.
- `/webapi/auth/sso-providers` lists the providers the sign-in page may offer.

## Changing what is supported

To support a new vendor, configure it in Admin as OIDC or generic OAuth 2.0; no code change is needed. A new protocol has to be added to `toGenericOAuthConfig` and to Admin's provider form and validation together, with tests in `tenant-sso.test.ts` and the `tenantSso` service tests.
