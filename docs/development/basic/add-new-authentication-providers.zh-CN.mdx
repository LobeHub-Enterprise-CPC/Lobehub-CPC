# 身份验证提供商（按租户配置的 SSO）

LobeHub 企业版没有内置的提供商预设（Google、GitHub、Microsoft、Auth0、Keycloak 等），也没有部署级的 SSO 环境变量。上游那种添加提供商的方式（在 `src/libs/better-auth/sso/providers` 下新增定义文件、配置 `AUTH_<PROVIDER>_*` 变量和 `AUTH_SSO_PROVIDERS`）在本代码库中已经不存在，这些变量也不会被任何代码读取。

每个租户自行配置登录提供商：Admin 把它们写入该租户的 `sso_providers` 表，客户端密钥按租户加密保存；租户自己的 [Better Auth](https://www.better-auth.com) 实例通过通用 OAuth 插件提供登录。

## 支持的提供商类型

| 类型           | `protocol` / `preset` | 需要配置的内容                                                                    |
| ------------ | --------------------- | -------------------------------------------------------------------------- |
| OIDC         | `oidc`                | Issuer（或 discovery 地址）、客户端 ID 与密钥。scope 默认 `openid email profile`，启用 PKCE。 |
| 通用 OAuth 2.0 | `oauth2` / `custom`   | 授权、令牌、用户信息三个端点，客户端 ID 与密钥。scope 默认 `profile email`。                        |

只要供应商支持这两种协议之一（Okta、Entra ID、Google、Keycloak、企业自有 IdP 等），就按其中一种配置。提供商 ID 只是租户管理员起的名字：叫 `okta` 或 `google` 的提供商就是普通的 OIDC 客户端，不会被当作厂商预设。库里其他类型的行（SAML、旧版本存下的命名 OAuth 2.0 厂商、配置不可用的行）会被单独跳过，不影响该租户的其他提供商。

## 回调地址

在身份提供商处登记的重定向地址：

```
https://<host>/t/<租户 slug>/api/auth/callback/<providerId>
```

请求代理会把它转发到该租户内 Better Auth 的通用 OAuth 回调（`/oauth2/callback/<providerId>`）。

## 代码位置

- `apps/server/src/services/tenantSso`：读取租户启用的行、解开密钥、执行 OIDC discovery（带 SSRF 防护），并把每一行转换成 Better Auth 的通用 OAuth 配置（`toGenericOAuthConfig`）。
- `src/libs/better-auth/tenant-sso.ts`：生成租户的提供商集合，跳过当前版本无法运行的行。
- `/webapi/auth/sso-providers`：返回登录页可以展示的提供商。

## 修改支持范围

要支持新的厂商，在 Admin 里按 OIDC 或通用 OAuth 2.0 配置即可，不需要改代码。要支持新的协议，需要同时修改 `toGenericOAuthConfig` 与 Admin 的提供商表单和校验，并在 `tenant-sso.test.ts` 和 `tenantSso` 服务测试里补用例。
